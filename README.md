# GVI Studio

Личная панель четырёх проектов на основе исходного Swiss-макета. Рабочий **локальный прототип**, а не подключённая система ГТО. Оригинальный JPEG-логотип сохранён без изменений и показывается целиком.

## Облачные задачи в Google Sheets

Подготовлен отдельный приватный вариант панели на Google Apps Script: общий список задач для компьютера и iPhone, вход владельца через Google, проверка конфликтов и перенос задач из локальной копии. Материалы и остальные разделы пока локальные. Таблица и развёртывание ещё не созданы в вашем Google-аккаунте.

**[Пошаговое подключение и ограничения](docs/GOOGLE-WORKSPACE.md)**. Команда `npm run build:google` собирает три готовых файла в `.local/apps-script`. Код не использует и не изменяет источники ГТО. GitHub Pages продолжает работать в прежнем локальном режиме.

## GitHub Pages — без сервера

Статическая версия работает по адресу проекта `/Gvi-studio/`: стили, логотип и модули используют относительные пути. На Pages доступны задачи, материалы, версии, ошибки, резервные копии и **явное синтетическое демо ГТО**. Node.js и ключи Google для этого не требуются. Режим подписан «Статическое демо · Google Sheets не подключены», кнопка «Пересчитать демо» пересчитывает только встроенные примеры.

Для существующего размещения Pages из ветки `main` достаточно обновления ветки; `.nojekyll` сохраняет прямую выдачу статических файлов. Настройки публикации в этой задаче не менялись. Открытие `index.html` через `file://` не поддерживается: модули должны загружаться по HTTP(S).

В `lib/runtime.js` статического сайта явно выбран `static-demo`. Node.js вместо этого файла отдаёт защищённый модуль с режимом `server`. Ошибка серверного API **не переключает** панель на статическое демо. Публичные демомодули содержат исключительно синтетические записи; реальные источники и ключи туда не помещать.

## Запуск Node.js — для серверного адаптера

Нужен Node.js 22+ и npm. В корне репозитория:

```sh
npm ci
npm start
```

Сервер слушает порт 3000 на компьютере, где его запустили. Откройте этот порт в браузере своим обычным способом. При этом способе запуска статистика загружается через серверный API. Сборка и база данных не нужны. Демо работает без Google, ключей и `.env`.

В облачной среде с недоступным стандартным npm-кешем используйте `npm ci --cache /workspace/.npm-cache`. Для другого порта: `PORT=3100 npm start`. Процессы нужно запускать заново в новой задаче Codex; зависимости сохраняются отдельно от процессов. Используйте существующий checkout; создавать Git worktree не требуется.

## Что работает

- Обзор с фильтром проекта, ближайшими, высокоприоритетными и просроченными задачами, историей и краткой статистикой ГТО.
- Четыре проекта и разделы задач, материалов, версий, ошибок и следующих действий. Создание, изменение, удаление.
- Задачи: описание, статус, приоритет, срок, материалы, этап, даты создания/изменения.
- Материалы: текст, ссылки, файлы до 2 МБ. Файлы скачиваются как вложения, не исполняются в странице.
- Версии: описания, материалы, ссылки на GitHub и результаты проверок. Сопоставление двух карточек; **автоматического diff файлов нет**.
- Ошибки: воспроизведение, ожидаемый/фактический результат, серьёзность, статус, версия, ссылка.
- «Точка старта»: карточки роликов, сценарии, сцены/длительности, раскадровки, промпты, генерации, публикации и ручные метрики. Для процентов обязательны период и определение.
- Сохранение в localStorage, JSON-экспорт/импорт с проверкой структуры и подтверждением замены, история последних 300 изменений. Стартовые 12 задач из макета обозначены примерами.
- ГТО: синтетические данные, отдельные даты регистрации и мероприятия, фильтры, агрегаты, качество данных, состояние обновления и ошибки. Протокол/A2 не изменяются.

## Ограничения хранения

Данные существуют только в этом браузере на этом адресе сайта. Они не синхронизируются с iPhone, не зашифрованы приложением и пропадут после очистки данных сайта. Заполнение квоты localStorage выдаёт ошибку и не подтверждает несостоявшееся сохранение. Рекомендуется держать небольшие файлы и регулярно экспортировать копию. Импорт до 10 МБ; фактическая квота браузера может быть меньше. В нескольких вкладках показываются изменения последней записи; совместного редактирования и разрешения конфликтов нет. Резервные копии храните приватно, не коммитьте их.

Следующий простой вариант постоянного хранилища: SQLite на том же Node.js-сервере + каталог вложений вне публичной директории, за авторизацией, с резервным копированием. Это даст одну базу для компьютера и iPhone без ещё одного облачного сервиса. **В текущей версии это направление, не реализованная синхронизация.**

## Подключение ГТО

Выбран Google Sheets API. Готового защищённого Apps Script в исходниках нет. Один небольшой сервер позволяет читать обе закрытые таблицы с read-only scope и отдавать только агрегаты. Открытый Apps Script endpoint не нужен.

1. Сначала согласуйте схему и правила из [docs/SOURCES.md](docs/SOURCES.md). `docs/source.example.json` — **предлагаемый контракт синтетического теста**, не предположение о ваших реальных столбцах.
2. Создайте отдельные приватные тестовые листы с синтетическими данными. Дайте сервисному аккаунту только роль читателя. Включите Sheets API в его Google Cloud-проекте.
3. Сохраните конфигурацию источников и credentials **вне checkout** с ограниченными правами. Предпочтительна платформенная service identity / ADC; если используется JSON-ключ, его нельзя помещать в репозиторий.
4. Используйте `.env.example` как список настроек. Для `sheets` нужны `GTO_CONFIG_PATH`, ADC или `GOOGLE_APPLICATION_CREDENTIALS`, `GTO_RULES_CONFIRMED=true` после согласования правил, `GVI_AUTH_USER`, `GVI_AUTH_PASSWORD_HASH`.
5. Хеш пароля: передайте длинный уникальный пароль в stdin `node scripts/password-hash.js` из защищённого менеджера секретов. Скрипт возвращает `salt:hash` (scrypt). Не передавайте пароль аргументом командной строки и не сохраняйте в shell history. Хеш храните в серверных настройках, не в Git. Пользователь вводит пароль в системном окне HTTP Basic браузера.
6. Рабочий сервер слушает только loopback. Для удалённого доступа обязателен HTTPS reverse proxy с TLS и ограничением частоты запросов. Не открывайте HTTP-порт рабочего режима в интернет. Все страницы и API защищены Basic; отсутствие хеша блокирует запуск `sheets`. Браузер может помнить вход до закрытия сессии. Для будущей многопользовательской версии лучше авторизация провайдера.
7. Проверьте отдельную синтетическую Google-таблицу и ожидаемые агрегаты. Только после этой проверки переключайте конфигурацию на реальные источники. Не расширяйте права выше читателя.

API источника обновляется максимум раз в 30 секунд. Фильтры применяются к последнему снимку на сервере. При сбое возвращается 503, прежний снимок обозначается устаревшим; если снимка нет, цифр нет. Демо никогда не подставляется вместо реальных данных. Клиент не получает строки, идентификаторы участников или credentials. При перезапуске сервера кеш исчезает.

Статические файлы выдаются по явному списку, серверный код, `.env`, исходники Google и документация через HTTP не доступны. У API есть только GET. Ошибки Google не печатаются в логи и не передаются браузеру. Категории выходят только из явно разрешённого списка; остальные объединяются в «Другая категория». Это не анонимизация для публичного доступа: даже агрегаты малых групп остаются за авторизацией.

## Проверки

```sh
npm run check
npm test
npm run test:browser
```

Playwright использует системный `/usr/bin/chromium`, если он установлен, или браузер из `.local/browsers`. Можно задать `CHROMIUM_PATH`. Для чистого компьютера:

```sh
PLAYWRIGHT_BROWSERS_PATH=.local/browsers npx playwright install chromium
# Дополнительная проверка WebKit, когда скачивание и системные зависимости доступны:
PLAYWRIGHT_BROWSERS_PATH=.local/browsers npx playwright install webkit
GVI_TEST_WEBKIT=1 npm run test:browser
```

Серверные браузерные тесты используют отдельный порт 3100; второй статический сервер на 3101 воспроизводит подпапку `/Gvi-studio/` без API. Основной тестовый сервер использует `GTO_MODE=demo`, изолированные браузерные контексты и только синтетические записи. Отдельно проверяются ресурсы в подпапке, отсутствие запросов к API в статическом режиме, создание задач и демофильтры. Playwright не записывает trace и автоматические снимки ошибок. Явные снимки сделаны только на демоданных.

## Что ещё не подключено

Реальные Google Sheets, проверка на внешней синтетической Google-таблице, чтение фактического протокола, синхронизация устройств, серверное хранение задач, МЭШ, Wordstat API, TikTok и другие внешние сервисы. Реальные ученики/аккаунты не используются. SEO-репозиторий и ветка Demo1 не предоставлены и не изменялись. Telegram отсутствует в архитектуре.
