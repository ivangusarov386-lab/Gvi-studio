# Личное облако GVI Studio в Google

Подготовлена интеграция **задач** с приватной Google-таблицей. Таблица ещё не создана в аккаунте владельца: в сессии Codex нет авторизованного Google Sheets/Drive-инструмента, а существующая переменная credentials не загружает Google API client. Развёртывание и реальная Google-авторизация не проверены. Код и тестовый пакет готовы к первоначальному запуску владельцем.

## Почему Apps Script

GitHub Pages остаётся публичной статической демоверсией. Приватная рабочая панель размещается в Google Apps Script и открывается под вашим Google-аккаунтом. Тот же интерфейс, оригинальный логотип, без отдельного платного сервера и без ключей в браузерном исходнике. Google даёт квоты Apps Script/Sheets; это личный рабочий инструмент, не система для большой команды.

Таблица задач отдельная от таблиц ГТО. Скрипт не знает ID источников ГТО и не обращается к ним. ГТО в этой сборке пока синтетический. Доступ к рабочей панели разрешён только владельцу: и настройкой развёртывания, и проверкой Google email на сервере. Открытый URL сам по себе прав не даёт.

## Первый запуск — один раз с компьютера

1. Откройте `script.google.com` под тем Google-аккаунтом, где должны храниться задачи. Создайте новый проект «GVI Studio».
2. Вставьте содержимое `Code.gs` из готового пакета в файл Code.gs. Создайте HTML-файл с именем **Index** и вставьте содержимое `Index.html`.
3. В настройках проекта включите показ `appsscript.json`; замените его содержимым файла из пакета. Он включает сервис Google Sheets API v4, часовой пояс Europe/Moscow и приватный webapp. В разделе «Сервисы» должен присутствовать Google Sheets API. При использовании собственного стандартного Cloud-проекта его Sheets API также должен быть включён.
4. Выберите функцию **setupWorkspace** и нажмите «Выполнить». Пройдите авторизацию своим аккаунтом. Запрашиваются доступ к Google-таблицам и email для проверки владельца; доступ к почте и Google Drive API не требуется. Сервис имеет право работать с таблицами, но код использует только созданный им ID. Проверьте запрошенные разрешения до согласия.
5. В Google Drive появится новая приватная таблица **«GVI Studio — рабочие задачи»**, лист **Tasks**. Повторный setup использует тот же ID, не создаёт новую таблицу и не стирает задачи. Не меняйте заголовки столбцов и прав доступа.
6. «Развернуть» → «Новое развёртывание» → «Веб-приложение»: выполнять **от вашего имени**, доступ **только я / Only myself**. Не выбирайте «Все»/анонимный доступ. Создайте развёртывание и откройте его URL.
7. В панели дождитесь «Задачи · Google Sheets». Создайте проверочную задачу. Откройте тот же Google-адрес на iPhone под тем же аккаунтом и нажмите «Обновить облако». Проверьте, что задача появилась, затем измените статус и проверьте компьютер.

Для последующих изменений код остаётся в GitHub/Codex. После обновления файлов Apps Script создайте **новую версию существующего развёртывания**, чтобы сохранить URL. GitHub Pages не превращается в облачную панель автоматически. Рабочую Google-ссылку можно добавить в закладки или на домашний экран iPhone. Секреты, пароли, коды Google и credentials не присылайте в чат.

Если корпоративная политика Google запрещает такие приложения или email текущего пользователя недоступен, скрипт отклонит вход. Это нужно решить на уровне аккаунта/политики, а не отключать проверку доступа.

## Перенос существующих задач

На старой странице GitHub Pages: Настройки → Экспортировать копию. В приватной Google-панели: Настройки → Импорт. Показывается число задач для добавления и запрашивается подтверждение.

Переносятся только задачи, изменённые/созданные вами (`sample=false`). Стартовые примеры, материалы, файлы, версии и ошибки автоматически не переносятся. Импорт добавляет новые ID; совпавшие ID с отличающимся содержимым дают конфликт, а не заменяют облачные задачи. Старые данные в браузере Pages остаются на месте.

## Хранение и синхронизация

- Один лист Tasks: id, project, title, description, status, priority, due, materials, stage, createdAt, updatedAt, sample. `materials` пока текст со ссылками/названиями.
- Максимум 2000 задач, до 40 000 символов на поле, общий JSON до 2 МБ. Файлы в таблицу не записываются.
- Панель читает задачи при открытии, возвращении на вкладку и раз в минуту, когда форма редактирования закрыта. Есть ручное обновление. Это не мгновенная совместная редактура.
- Изменения подтверждаются только после ответа Google. При потере ответа результат записи может быть неизвестен: сначала обновите облако, затем повторяйте действие.
- ScriptLock сериализует операции панели. Хеш текущего состояния проверяется перед записью; устаревший снимок не может затереть новое состояние другого устройства.
- Вся таблица задач записывается одним атомарным `spreadsheets.batchUpdate`. Ячейки используют stringValue/boolValue; текст `=...` не исполняется как формула.
- Правьте задачи через панель. Google не блокирует ручное редактирование владельцем таблицы: ScriptLock не защищает от одновременного ручного редактирования ячеек. При обнаруженном изменении заголовков/типов доступ останавливается с ошибкой структуры.
- Облачные задачи не сохраняются в localStorage автоматически, только в памяти страницы. Экспорт по вашему нажатию включает текущий снимок задач. История операций пока локальная.
- Материалы/файлы, версии, ошибки и ролики пока локальны и могут быть удалены при очистке браузера. Явное предупреждение есть в интерфейсе.

## Сборка и проверки для Codex

```sh
npm ci
npm run build:google
npm test
npm run test:browser
```

Готовые три файла: `.local/apps-script/Code.gs`, `Index.html`, `appsscript.json`. Сборка включает CSS, JS и оригинальный логотип; приложение не загружает frontend из GitHub Pages. Генератор не читает `.env`, пользовательские данные или credentials. В Git хранятся исходники и инструкции; `.local` игнорируется.

В проверках Apps Script сервисы заменены тестовыми реализациями. Проверены чтение/запись/удаление, конфликт двух снимков, проверка владельца, отказ при неверной схеме, типизация ячеек без формул. Playwright проверяет приватную сборку с подменённым `google.script.run`: два браузерных контекста, сохранение, обновление, конфликт с сохранением текста формы и отказ при ошибке входа. Эти проверки **не доказывают работу в настоящем Apps Script** — после первого развёртывания нужен пункт 7.

## Следующие полезные шаги

1. Приватная папка Google Drive для файлов; ссылки и метаданные — в таблице. Затем материалы, версии, ошибки и ролики станут общими на устройствах.
2. Недельный обзор задач: «сегодня», «на этой неделе», «просрочено», доска по статусам. Без новых внешних сервисов.
3. История изменений и регулярная резервная копия в вашей приватной папке. Доступы и срок хранения согласовать перед автоматизацией.
4. Если понадобится много пользователей, сложные права или большой объём, перейти с Sheets на полноценную базу. Для текущих личных задач Sheets + Apps Script достаточно.
